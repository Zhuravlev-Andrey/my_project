# System Patterns

## Архитектура (текущая)

- Одномодульное Compose-приложение: `MainActivity` → `MyApplicationTheme` → `Scaffold` → `Greeting`.
- Ограничение: приложение полностью офлайн, без сервера и сети (ADR-004).
- Edge-to-edge включён; тема использует dynamic color на Android 12+ по умолчанию.
- Продуктовый слой отсутствует: UI-шаблон и модель данных не связаны.

## Планируемая модель данных (MVP на основе `start.kts`, не в сборке)

- Нормализованная схема Room: справочники → шаблоны → пользовательские данные → журнал.
- Все id — `Long` autoGenerate, `0` = не сохранён.
- Вес — кг (`Double`), время — `Long` UTC-мс; enum Room хранит текстом.
- В факте (`SessionSet`) вес — снимок числом, чтобы правка сетки не меняла историю.
- Для максимума (`ExerciseMax`) хранится ссылка на `WeightOption` + дата; история не перезаписывается.
- Прогрессия — отдельное правило на упражнение, не более одного.
- Каскады: удаление тренажёра чистит его сетку; удаление используемых упражнения/схемы запрещено (RESTRICT).
- MVP-схема без `MuscleGroup`/`ExerciseMuscle`; мышечные группы добавляются позже миграцией (ADR-006).
- Добавляется `SessionExercise`: сессия + упражнение + порядок + заметка + статус (ADR-005).
- Календарь MVP показывает только следующую тренировку по программе, без расписания.
- Экспорт/импорт входит в MVP; формат и механизм определяются на этапе 2.

## Процесс

- OpenSpec схема `spec-driven`; поведение — в `openspec/specs/`, изменения — в `openspec/changes/`.
- Спеки пишутся в Given/When/Then, артефакты и UI — на русском.

## ADR

- ADR-001: OpenSpec `spec-driven` — подтверждено `openspec/config.yaml`; дата: TODO.
- ADR-002: офлайн-хранение на Room — из черновика `start.kts`, не реализовано; дата: TODO.
- ADR-003: снимок веса в журнале вместо ссылки на сетку — причина: неизменность истории; дата: TODO.
- ADR-004: полностью офлайн — данные только в локальной Room/SQLite, без сервера, сети, аккаунтов и синхронизации — причина: требование владельца и работа без интернета; следствие: серверные пункты чек-листа не применимы, бэкап — экспорт/импорт — дата: 2026-11-25.
- ADR-005: заметка и статус упражнения хранятся в `SessionExercise` (сессия + упражнение + порядок + заметка + статус) — причина: нужна заметка после каждого упражнения и снимок статуса для истории; альтернатива — заметка только на сессии или на подходе — дата: 2026-11-25.
- ADR-006: в MVP-схеме нет `MuscleGroup`/`ExerciseMuscle`; мышцы добавляются позже миграцией — причина: в MVP мышцы не указываем; альтернатива — оставить неиспользуемые таблицы — дата: 2026-11-25.

Формат новой записи: `ADR-NNN: решение — причина — дата`.
